# The brief

Four decisions, asked before any code. They are here because each one changes
work that is expensive to redo: the audience changes the copy, the market
changes which language loads first, the stack changes everything, and the
content state changes whether you are building a shell or a site.

Ask them together, as multiple choice with an escape hatch, not as an
interrogation spread over four turns. Offer a recommendation on the stack;
most people do not have a view and would rather you decided.

## 1. What is it for

- Land a full-time role → detailed process, clear seniority signal
- Win freelance work → outcomes, credibility, an easy contact path
- Sell workshops or training → the offering, testimonials, a booking path
- Personal brand → memorability over completeness

Multi-select. Most people pick two, and the pair tells you what to lead with.

## 2. Which market

Decides which language loads first and how much local context the case studies
can assume.

- Local → local language first, company names carry weight unexplained
- International or remote → English first, and the cases must read to someone
  who has never heard of the companies
- Both → detect from the browser, neither treated as fallback

## 3. Language

Monolingual, or bilingual with a toggle. Bilingual is roughly 1.5x the content
work and needs the type system to carry both scripts. If either language is
RTL, say so now: it affects layout primitives, not just strings.

## 4. Content state

The one people are least honest about, so ask it directly.

- Written up already → build the real thing
- Visuals but no writing → you will be drafting case-study copy
- Scattered → start with an inventory pass
- Nothing → build the shell with labelled placeholder slots

## Then confirm the read back

State the combination in one line before starting, so a wrong assumption
surfaces now rather than after a day of building. For example: full-time role,
international, bilingual with RTL, three projects written up.

## Structure and visual direction

Ask these two as previews rather than descriptions. People cannot evaluate
"editorial" or "bold and graphic" as words, but they can point at an ASCII
mockup instantly, and the choice they make from a picture is the one they
actually meant.

Offer home-plus-case-study-pages as the default. It is what hiring managers
expect and it gives each project room. A single scrolling page keeps every case
shallow, which is the wrong trade for this audience.
